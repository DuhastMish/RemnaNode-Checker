# nodecheck

Проверка доступности нод Remnawave / Open60 **из разных сетей**: домашних провайдеров, мобильных сетей,
дата-центров. Панель забирает список нод из ваших панелей-источников, а лёгкие чекеры в нужных сетях
проверяют ноды и присылают результаты. Панель сводит их в один цвет, ведёт инциденты и шлёт алерты.

```
Remnawave / Open60 ──sync──▶ Панель (UI, агрегация, алерты, экспорт) ◀──HTTPS── Чекеры (дом, моб. сеть, ДЦ…)
```

- `admin.example.com` — вход по admin-токену: ноды по вкладкам источников, карточки с историей и
  инцидентами, связывание нод, ручные проверки, источники, чекеры, настройки, терминал.
- `status.example.com` — вход по PIN: плитки нод и проверка одного адреса.

**Установка — [docs/DEPLOY.md](docs/DEPLOY.md).** Как устроено внутри — [docs/INTERNALS.md](docs/INTERNALS.md).

## Возможности

- Несколько источников, в том числе несколько панелей одного типа: каждая — своя вкладка.
  Синхронизация по расписанию, кнопкой для источника или для одной ноды.
- Нода имеет постоянный `node_id` и не зависит от IP. При смене адреса в источнике история и
  инцидент сохраняются, а проверка нового адреса ставится сразу.
- Ручное связывание одной физической ноды из разных источников: проверка одна, на вкладках ноды
  показываются отдельно.
- Чекеры: регистрация в панели с одноразовым показом токена, только исходящие соединения, список нод
  хранится в памяти, адреса не пишутся в логи. Чекер можно отключить или перевыпустить ему токен.
- Проверки: SSH-проба (доходит ли TCP и SSH-handshake) и проба через HTTP-прокси ноды.
- Итог по всем чекерам: зелёный / оранжевый (видят не все) / красный / серый, инциденты, вебхук-алерты,
  экспорт состояния обратно в источники.

## Цвета

| Плитка | Значит |
|---|---|
| зелёный | ни один online-чекер не считает ноду упавшей |
| оранжевый | часть чекеров считает ноду упавшей |
| красный | все чекеры считают ноду упавшей |
| серый | нет свежих результатов |

Чекер считает ноду упавшей после двух не зелёных результатов подряд. Результат одного чекера:
зелёный — работает (прокси, а если его нет — SSH); жёлтый — SSH есть, прокси нет; красный — ничего.

## Алерты

`POST <URL из «Настройки → Алерты»>`, `Authorization: Bearer <токен>` (если задан).

```json
{"type": "node", "event": "down | changed | up", "text": "[DOWN] DE-1 (Main) 1.2.3.4: недоступна у части чекеров (видят 1 из 2)",
 "node_id": "uuid", "incident_id": 12, "color": "orange", "prev_color": "green",
 "address": "1.2.3.4", "address_at_open": "1.2.3.4", "checkers_up": 1, "checkers_down": 1,
 "sources": [{"source": "Main", "name": "DE-1", "external_id": "uuid-в-источнике"}], "ts": 1762500000}

{"type": "checker", "event": "offline | online", "text": "[CHECKER OFFLINE] Дом пропал: …",
 "checker_id": "uuid", "name": "Дом", "last_seen_at": 1762500000, "ts": 1762500090}
```

`down` — открыт инцидент (нода стала оранжевой или красной), `changed` — оранжевый ↔ красный,
`up` — инцидент закрыт; если адрес за время инцидента сменился, это указано в `text`.

## Экспорт

Раз в интервал плановой проверки каждому источнику с заданным «Экспорт: URL приёма»:

```json
POST <url>   Authorization: Bearer <токен экспорта>
{"source": "Main", "source_type": "remnawave", "ts": 1762500000,
 "nodes": [{"external_id": "uuid-в-источнике", "node_id": "uuid", "name": "DE-1", "address": "1.2.3.4",
            "state": "green | orange | red | grey", "checkers_up": 2, "checkers_down": 0,
            "incident_id": null, "checked_at": 1762499990}]}
```
